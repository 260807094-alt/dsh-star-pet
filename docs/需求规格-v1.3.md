## 三、派生量（`deriveModel` 算出的 18 个常量）

配置是「用户填的」，派生量是「程序按配置算出来、后续反复用的」。改配置后全部重算一次。

| 变量 | 公式 | 默认值下 | 含义 |
|---|---|---|---|
| `startMin` | `parseHHMM(work_start)` | 540 | 上班，从 0 点起算的分钟 |
| `endMin` | `parseHHMM(work_end)` | 1020 | 下班 |
| `lunchMin` | `clamp(lunch_minutes, 0, 300)` | 90 | 午休时长 |
| `lunchStartMin` | `parseHHMM(lunch_start)` | 690 | 午休开始 |
| `lunchAfterMin` | `(lunchStartMin − startMin)` 取正 | 150 | 上班多久后开始午休 |
| `onSite` | `endMin − startMin` | 480 | 待在公司的分钟数 |
| `lunchOverlap` | 午休 ∩ [上班, 下班] 的长度 | 90 | 真正扣掉的午休 |
| `paidMin` | `onSite − lunchOverlap` | 390 | **净工时**（分钟） |
| `daily` | `monthly_wage ÷ pay_days_per_month` | 459.77 | 日薪 |
| `netSec` | `paidMin × 60` | 23400 | 净工时（秒） |
| `perSec` | `daily ÷ netSec` | 0.019648 | **每秒** |
| `perHour` | `perSec × 3600` | 70.7339 | 时薪 |
| `weekdays` | `work_weekdays` | [1..5] | 上班日集合 |
| `otOn` | `overtime_enabled === true` | false | 加班总开关 |
| `otDays` | `overtime_weekdays` | [1..5] | 加班日集合 |
| `otWorkRate` | `overtime_rate_workday` | 1.5 | 上班日倍率 |
| `otRestRate` | `overtime_rate_weekend` | 2 | 非上班日倍率 |
| `ot*Min` ×4 | 四个加班时段 | 19:00/21:00/09:00/17:00 | 两对加班窗口 |

**算例（默认配置）**

```
日薪  = 10000 ÷ 21.75              = 459.77
净工时 = (17:00−09:00) − 午休90分   = 390 分 = 23400 秒
每秒  = 459.77 ÷ 23400             = 0.019648 元
时薪  = 0.019648 × 3600            = 70.73 元
```

## 四、计算链（从「现在几点」到「该显示什么」）

`snapshot(model, now)` 每次刷新算一遍。

### 4.1 判定今天是什么日

```
workday  = work_weekdays 里有今天吗
otDay    = overtime_weekdays 里有今天吗
```

### 4.2 判定处于哪个阶段（`phase`，7 种）

| phase | 中文 | 触发条件 |
|---|---|---|
| `before` | 还没上班 | 上班日，现在 < 上班时间 |
| `working` | 搬砖中 | 上班日，上班 ≤ 现在 < 下班，且不在午休 |
| `lunch` | 午休中 | 落在午休区间内（上班日和加班日都可能） |
| `after` | 已收工 | 上班日过了下班，或非上班日过了加班结束 |
| `idle` | 休息中 | 上班日已下班、还没到加班开始 |
| `overtime` | 加班中 | 在加班窗口内 |
| `rest` | 今天休息 | 非上班日且不在加班窗口 |

判定顺序（后写的覆盖先写的）：默认 `working` → 上班日按时间改 → 非上班日先设 `rest` → 加班开关关/非加班日/时段写反 → 倍率归零 → 下班后加班前 → `idle` → 进了加班窗口 → `overtime`/`lunch` → 非上班日加完 → `after`。

❓ **Q6**：`idle`（休息中）只在「上班日 + 已下班 + 今天有加班 + 加班开始晚于下班」时出现。默认配置（下班 17:00、加班 19:00）17:00~19:00 就是 `idle`。这个状态区隔是你要的吗？

### 4.3 算工时的两条独立线

**基础工时**（`baseWorked`，只算上班时段，不含加班）

```
现在 ≤ 上班时间        → 0
否则 取 min(现在, 下班) − 上班 − 与午休重叠的部分
```

**加班工时**（只算加班窗口，扣掉落在窗口内的午休）

v1.3 只保留**一个**函数，全插件所有加班工时都走它（`core.js` 的 `otSec`）：

```
otSec(model, startMin, uptoMin, endMin)
  hi    = min(uptoMin, endMin)
  return max(0, hi − startMin − 落在 [startMin, hi] 内的午休) × 60   // 秒
```

三个调用点只差 `uptoMin`：

| 用途 | 调用 | 含义 |
|---|---|---|
| 今天加班总额 | `otSec(m, 开始, 结束, 结束)` | 整段加班有效秒数 |
| 今天已加班 | `otSec(m, 开始, 现在, 结束)` | 从加班开始到现在 |
| 当月某天加班 | `otSec(m, w.start, w.end, w.end)` | 同第一行，换个加班窗口 |

默认配置：上班日加班 19:00–21:00 = 120 分，无午休重叠 → 7200 秒；非上班日加班 09:00–17:00 = 480 分，扣 90 分午休 → 390 分 = 23400 秒。

### 4.4 进度条

```
上班日   → progress = 已工作 ÷ 净工时        （封顶 100%）
非上班日 → progress = 已加班 ÷ 加班有效总长  （封顶 100%）
```

### 4.5 已赚（大金额）

统一成「绿 + 蓝」两段，绿段是基本工资、蓝段是加班工资，两段互不重叠：

```
earnedBase = 上班日 ? 日薪 × progress : 0
earnedOt   = 加班窗口有效 ? perSec × 倍率 × otSec(开始, 现在, 结束) : 0
earned     = earnedBase + earnedOt
```

`earnedOt` 用的是「到现在为止已经加班的那部分」，所以加班中它会跟着秒数往上涨；倍率为 0 时恒为 0。

### 4.6 日薪格 + 窝囊费

v1.3 起**不再有「rateBase / rateExtra」拆分**。加班费只有一个算法：

```
otPay(model, startMin, uptoMin, endMin, rate) = rate > 0 ? perSec × rate × otSec(...) : 0

dayBase = 上班日 ? 日薪 : 0
dayOt   = otPay(加班开始, 加班结束, 加班结束, 倍率)      // 全天加班费
dayTotal = dayBase + dayOt
窝囊费   = dayOt                                        // 同一笔钱，不另设变量
```

口径（用户 m01745 裁定「读法 A」）：**倍率就是字面倍数**，N 倍 = 加班时段按 N 倍时薪计。

| 倍率 | 上班日 绿 | 蓝 | 非上班日 绿 | 蓝 |
|---|---|---|---|---|
| 0 | 459.77 | 0.00 | 0.00 | 0.00 |
| 1 | 459.77 | 141.47 | 0.00 | 459.77 |
| 1.5 | 459.77 | 212.20 | 0.00 | 689.66 |
| 2 | 459.77 | 282.94 | 0.00 | 919.54 |

档位只有四档（`OVERTIME_RATES = ["0","1","1.5","2"]`）。需求⑥的「3 倍也可以去掉了」已落实：`sanitizePatch` 收到 `"3"` 时回落为默认档。

「本月还可赚」的蓝段用同一个 `otPayForDay` 逐日累加，所以三处（日薪格蓝段、窝囊费、本月蓝段）永远是同一个口径。

### 4.7 本月剩余

```
remDays    = 本月剩余（含今天）里 work_weekdays 命中的天数 − (今天已满勤 ? 1 : 0)
monthBase  = max(0, remDays × 日薪 − earnedBase)
monthOt    = max(0, 本月剩余每天 otPayForDay 之和 − earnedOt)
monthTotal = monthBase + monthOt
```

Q8 已定（扣掉今天已赚的）：恒等式 `monthTotal + earned` 在一天之内保持常数。
实测（默认配置 + 加班开，11-09）：08:30 → 20:30 的 `monthTotal + earned` 恒为 **10751.55**；
17:30 下班后 `remDays` 从 16 变 15、`monthBase` 从 7250.22 落到 6896.55。
11-30（月内最后一个工作日）17:30：`remDays 0`、`earned 459.77`、`monthBase 0`（只剩当天加班 212.20）。

### 4.8 每秒速度（`secRate`）

```
加班中   → 每秒 × 倍率
上班日   → 每秒
其他     → 0
```

Q9 已定（用户 m02116 同意）：`phase` 是 `lunch` / `before` / `idle` / `after` 时 `secRate` 归 0，副标题显示「每秒 ¥0.0000」，与大金额纹丝不动的表现一致。实现见 `core.js` `snapshot` 末尾的三元。

### 命名问题（v1.3 已统一，见下表）

v1.3 采用 **3×2 命名矩阵**：前缀表示时间范围，后缀表示「是不是加班费」。

| 前缀 | 时间范围 |
|---|---|
| `day*` | 今天一整天（可能还没走完） |
| `earned*` | 今天到现在为止已经赚到的 |
| `month*` | 本月剩余（含今天） |

| 后缀 | 含义 |
|---|---|
| `*Base` | 基本工资 → 绿色 |
| `*Ot` | 加班工资 → 蓝色 |

所以六个金额就是 `dayBase / dayOt / earnedBase / earnedOt / monthBase / monthOt`，再加三个合计 `dayTotal / earned / monthTotal`。窝囊费就是 `dayOt`，**不再单设变量**。

已清掉的旧名：

| 旧名 | 处理 |
|---|---|
| `dailyBase` / `dailyOt` / `dailyTotal` | 改名 `dayBase` / `dayOt` / `dayTotal` |
| `otDaily` | 删（与 `dayOt` 同值，窝囊费直接用 `dayOt`） |
| `otOverBase` | 删（冗余别名） |
| `rateBase` / `rateExtra` | 删（统一进 `otPay` 一个函数） |
| `otSpanMin` / `otWorked` / `otEarned` | 删（需要时调 `otSec`） |
| `monthLeft` | 改名 `monthTotal` |
| `monthRemaining()` / `workedSeconds()` | 删（内部函数不再导出） |
| `SPRITE_FRAMES` / `DAY_MIN` / `ymd()` | 删（全仓无人使用） |

### 配置字段命名问题

| 现名 | 问题 |
|---|---|
| `overtime_rate_weekend` | 实际含义是「**非上班日**」，非上班日不一定在周末（比如调休的周三） |
| `banter_mode` 的值 `"workday"` / `"allday"` | `"workday"` 其实是「上班或加班时」，不精确 |
